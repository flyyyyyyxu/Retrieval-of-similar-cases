# 本地金融借款案例接入

## 数据与启动

运行 `./scripts/dev-local.sh`，访问 http://127.0.0.1:8000 。也可将汇总 JSON 路径作为第一个参数传入；相同目录需提供 `案例分析.json`。

- 汇总：25件文书，5组各5件，814段原文。
- 分析：25份案情概要、25份案例分析，明确标为 AI 归纳，每段附源文书 ID、段落 ID 和原文引用。
- 导入结果：`var/local_cases.json`；检索与报告记录：`var/local-demo.db`。两者均不进 Git。
- 本地入口显式设置 mock 数据源及金融借款词表，关闭外部模型与重排请求。不会修改 `.env` 或原始文书。

仅重新导入数据：

```bash
cd backend
uv run python ../scripts/import_local_cases.py /完整路径/全部案件.json
```

导入器不改原文文本和段落 ID，清理法院名称前缀，按说理、主文及落款重新划分段落区域。只有明确标识的事实段落会进入“本院查明”，其余未精细分区的正文仍在全文中保留。地域筛选支持省级前缀，法院层级兼容“基层法院”和“基层人民法院”。

## 展示与分析边界

结果卡片提供“案例分析”“案情概要”及可用原文栏目；AI 段落注明归纳身份，仅保留“定位原文”，不再重复展示编号引用。各栏目按自己的段落依据定位，跳过空引导标题；概要优先定位主文，分析定位对应说理，所有支持引文仍由接口保存。

综合答复分为“总结、裁判观点、案例比较”。本地文书已补充38项按争点拆分的裁判结论和关键事实，均附原文依据。生成时只使用本次命中结果，在同一争点下选取最多3件文书，并在可用范围内保留不同处理结果；总结概括实际处理，观点列出各案结论，比较对照双方事实和约定。仅有1件有效文书时明确说明不能形成多案比较；没有有效观点时保留 pending。不同请求范围的结果不直接解释为裁判冲突。

上方答复统一按“文书ID＋段落ID”编号，引用的可访问名称注明案号，避免不同文书都从 `[1]` 开始造成误解。旧版历史答复在恢复时重新获取三部分内容。

引用在导入、mock 加载及综合答复生成时校验：案例 ID 必须一致、引句必须存在于指定段落、引用与段落列表须一致。引用校验只证明原文存在，不代替对归纳内容的法律复核。程序性再审裁定的摘要明确说明实体说理不足。

来源仍为普通裁判文书 `judgment`，缺失的公开来源链接继续为空。真实案例不会因离线使用而标成虚构案例或指导性案例。报告数据库名称相应显示为本地案例库，报告正文仍采用原文摘录。

## 验证

- `cd backend && uv run ruff check . && uv run pytest`。
- `uv run python ../scripts/export_openapi.py` 更新接口定义。
- `uv run python ../eval/run_eval.py` 保留原有虚构样本基线；现有两条评测问题不代表金融借款检索质量，真实库仍待独立人工相关性标注。
- 启动本地入口后运行 `node frontend/qa/local-cases-check.cjs`；如未全局安装 Playwright，通过 `PLAYWRIGHT_MODULE` 指向本机安装包。

浏览器检查覆盖首页示例、真实本地检索、分析摘要、引用定位、安徽地域与基层法院筛选、窄屏布局及生成文本转义。私人文书、生成数据与分析保留在本机，通用测试只使用虚构样本。
