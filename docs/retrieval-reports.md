# 检索报告

## 用户流程

- 相关案例行提供“收藏”和“加入检索报告”两个独立按钮，后者再次点击可移除。收藏需选择收藏夹，和报告篮分别保存。全选旁边是生成图标和已加入数量，悬停/键盘聚焦显示“生成检索报告”。勾选和加入报告是两个动作；工具栏支持将勾选项批量加入，重复加入不重复计数。
- 报告篮按本次检索隔离，切换筛选不丢失已加入项；历史快照只保存案例ID。新检索清空报告篮；生成后的报告是独立快照，后来移除案例不会改动已生成报告。
- 生成后进入在线编辑，支持标题、加粗、斜体、下划线、删除线、列表、对齐、撤销/重做。点击保存后，可从“我的报告”继续编辑；有未保存修改时关闭/刷新浏览器会提醒。
- Word/PDF按钮先保存点击时的编辑快照，再下载该版本。保存失败保留编辑内容并显示错误，不继续下载旧版本。保存期间继续输入的内容仍标记为未保存。

## 内容与可信边界

默认报告结构为报告主题、日期、完成人、数据库、检索条件/过滤条件、报告概况、案例层级统计、相关类案、引用法规、案例索引。完成日期按Asia/Shanghai；完成人留空供填写。

生成器直接整理所选案例的源文书，不调用模型。案号、法院、日期、裁判段落、法规条文只从数据源读取，缺失不补造。裁判理由和结果带文书内段落ID；法规来自所选文书的law_references，按名称/版本/条文内容区分。未提供法规时保留补充位置。

层级统计互斥计数：指导性、官方典型优先分类；其余按法院级别分类，缺失级别单独列出。总数与报告纳入案例数一致。真实底库字段映射仍待审计。

报告生成后属于可人工修改的文稿，保存和下载不会声称人工改写仍是经过程序核验的AI结论。报告保留来源摘录说明和文书ID，复核由用户完成。

## 接口与存储

契约以backend/app/schemas.py及docs/openapi.json为准。

| 接口 | 用途 |
|---|---|
| POST /api/reports | search_id、case_ids、filters生成报告 |
| GET /api/reports | 已保存报告列表 |
| GET /api/reports/{id} | 读取完整可编辑报告 |
| PUT /api/reports/{id} | title、ops、revision保存编辑稿 |
| GET /api/reports/{id}/download?format=docx或pdf | 下载已保存版本 |

- 案例ID必须属于本次搜索快照，生成时读取当前相同数据源；文书读取失败不静默漏掉该案例。case_ids去重，最多50篇。
- ops是受限Quill Delta：文本、已知文字/段落格式和层级图嵌入。不接受任意HTML、图片、视频、事件属性或未知格式；总文本不超过50万字。HTML特殊字符在导出时转义。
- reports表保存在配置的SQLite中，不进Git。revision乐观锁避免不同窗口静默覆盖；版本冲突返回409，前端保留未保存文本。
- 应用沿用本地团队Demo的运行方式，未增加账号/多人权限系统。

## 实现与导出

Quill 2.0.3的官方发行文件和BSD许可证随frontend/vendor/quill提供，编辑器运行不请求CDN。后端用python-docx生成真正的.docx，用ReportLab生成真正的.pdf；PDF使用随仓库提供的开源中文字体并嵌入使用字形。字体的OFL许可证和构建说明在backend/assets/fonts。

Word的层级统计使用可编辑的逐层色带，PDF/编辑器使用梯形层级图。两种导出共用Delta段落解释器，支持同一份编辑内容的文字与基本格式。无需LibreOffice、打印对话框或外网服务即可下载。浏览器编辑区和分页文件的分页位置可以不同。

## 验收

- backend/tests/test_reports.py：所选案例与原文、统计计数、保存/版本冲突、真实DOCX/PDF、越界案例、不可读取文书、禁止未知属性/嵌入。
- frontend/qa/report-check.cjs：计数增减/批量去重、生成、工具栏键盘操作、输入/保存/刷新、报告列表、实际Word/PDF下载、手机布局、无外网编辑器请求。
- 隔离mock验证：后端51项测试与Ruff通过；report、api-flow、reference-library、workspace-panels四份浏览器脚本通过。
- 实际下载文件经文本检查，人工修改同时进入Word/PDF；PDF字体嵌入已检查。Word经过render_docx.py渲染，PDF经过Poppler渲染并逐页检查中文、层级图、页码和分页。QA导出和截图均被Git忽略。
