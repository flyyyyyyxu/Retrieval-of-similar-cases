# 清案 · 类案检索 HTML 原型

第一阶段交付：无构建依赖的 HTML / CSS / JavaScript 原型。暂定产品名「清案」，未连接真实案例库、后端或模型。

## 打开

直接在浏览器打开 `index.html`，或在本目录运行：

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory .
```

访问 http://127.0.0.1:4173。采用 hash 路由，不需要服务端路由配置。

## 页面与流程

- `#/`：产品介绍首页，场景切换、产品预览、检索流程与入口。
- `#/search`：输入问题、选择示例、展开地域／年份／法院层级／案由。
- `#/results`：模拟检索、筛选、排序、摘要、案例及法条。
- `#/case/labor-1/4`：案例详情，最后的数字表示段落索引；`4` 定位「本院认为」。
- `#/history`：重新打开检索，恢复筛选、排序与已记录的位置。
- `#/saved`：收藏案例及重新打开。

主链路：介绍页 → 检索 → 处理状态 → 结果 → 文书或法条 → 返回原结果。

## 已实现

- 三类演示场景：劳动争议、合同纠纷、民间借贷，共 12 条虚构案例。
- 案例的事实／观点／结果切换、摘要展开、差异提示。
- 实际影响结果的四项筛选，以及关联程度、日期升降序排序。
- 分析引用与案例、法条一致；目录定位、段落高亮、法条抽屉及关联案例。
- 收藏、取消收藏、历史记录、删除单条历史、复制引用。
- 返回结果保留条件、排序及滚动位置。
- 初始、空输入、加载、无结果、失败及重试状态。点击工作区右上「交互原型」可体验边界状态。
- 本地存储仅保存当前浏览器的历史和收藏；无账号及跨设备同步。
- 桌面与窄屏适配、键盘焦点、对话框焦点约束与 Escape 关闭。

## 文件结构与后续对接

- `index.html`：HTML 入口。
- `styles.css`：品牌、首页、工作区及响应式样式。
- `data.js`：集中维护的案例与条文示例。
- `app.js`：页面、交互、浏览器存储及模拟 repository。
- `.openai/hosting.json`：静态托管声明。
- `qa/`：验收脚本与本地截图（截图不进入部署）。

后续可把 `repository.search(query, filters)` 替换为真实 API 调用，再逐步增加分页、服务端筛选、引用段落标识及后端持久化；本轮不预建这些功能。

## 数据边界

所有案例为虚构示例，案号明确带「演示」标识；法条为未实时核验的节选，部分经过缩略。模拟分析与文书示例分开展示，不能作为真实法律结论或完整法条使用。

## 本轮界面精简

- 首页改为产品说明与可操作的场景问题，移除模拟工作区预览、重复介绍区和底部重复 CTA。
- 桌面工作区移除通用页头与访客头像，只保留页面自身标题；有已完成结果时提供「当前检索」入口，新建草稿不清空上一份结果。
- 摘要默认收起，筛选按需展开，案例列表提前进入首屏。空历史不显示占位区。
- 法条与原型说明使用原生 dialog/showModal；提供 closedby 渐进增强与不支持浏览器的边界点击回退。
- 搜索采用 search/form 语义、显式标签和错误关联，中文输入法组合状态不会触发快捷提交。
- 依照 Modern Web Guidance 的 css-layout、forms、dialog、content-first-noise-reduction 指导完成核对。
